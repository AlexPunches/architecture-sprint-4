# Мотивация

Первая проблема, которую нам необходимо решить -- это найти причину потери заказов.

В первую очеред добавим логирование в `MES API`, 
поскольку в этом сервисе заказ проходит больше всего статусов, возможно на одном из них о теряется.

При возможности, постараемся добавить логирование для сервиса `CRM API`. Это тоже очень вероятная точка отказа. 

Логирование поможет 
- сократить количество потеряных заказов
- увеличисть скорость решения инцидентов
- сократить количество ошибок в коде. Логирование поможет выявлять ошибки, чтобы устранять их.

Список логов
- заказа добавление: время, id-заказа, id-покупателя 
- назначение заказа оператору: время, id-заказа, id-оператора
- выполнение заказа оператором: время, id-заказа, статус-заказа
- упаковка заказа: время, id-заказа
- отправка заказа: время, id-заказа, id-покупателя 
- завершение заказа: время, id-заказа


# Предлагаемое решение

Используем стек ELK.  

Доступ к логам будут иметь только DevOps и Бэкенд-инженеры. 
DevOps чтобы настраивать сбор логов, а Бэкенд-инженеры чтобы испльзовать логи для исправления ошибок.

Чувствительные данные маскируем.  

Настроим алертинг на логи со статусов FATAL. Возможно как временная мера, пока приложение не станет стабильным.
Алертинг Фаталов позволит выявить и исправить ошибки в приложении.
